REGOLA: Se dichiaro una classe che estende una StatefulWidget devo dichiarare due classi,
        una in cui dichiato la classe e la seconda dove dichiaro lo stato usato dalla prima classe


Ogni volta che si vuole cambiare lo stato di una classe si deve usare il metodo "setState", questo permetterà l'aggiornamento grafico (sul dispositivo) del valore della varibile all'interno dello stato

CICLO VITA componenti

- createState
- initState (richiamato una sola volta quando il compnente viene creato. Permette di inizializzare delle varibili o di richiamare delle funzioni all'avvio del componente)
- build (costruisce la grafica del componente)
- dispose (richiamato quando il componente non è più visibile)

Lifecycle principale

Ordine:

__________________________________________________________
-> initState()

Chiamato UNA volta, perfetto per:
    - fetch iniziale
    - controller
    - animation
    - listener

__________________________________________________________
-> build()

    Può essere chiamato:
        - continuamente
        - molte volte
    Deve essere:
    - veloce
    - puro
    - senza side effects

__________________________________________________________
-> dispose()

    Serve per pulire:
        - stream
        - controller
        - animation
        - listener

__________________________________________________________
-> didUpdateWidget()

    Usato quando:
    - il parent rebuilda
    - arrivano nuove props

   --> PASSING DATA via FUNCTION ACCROSS WIDGET <--

   Si può sfruttare questo scenario interessante

   Ho un componente genitore in un posso diarare una list di un certo tipo,
   definire una funzione se aggiunge elemnte a questa list
   e passare ad un componente figlio questa funzione, tramire suo costruttore, 
   in modo tale che sia il componente figlio a chiamare tale funzione passando dei parametri definiri nel componente figlia.
   A fine di questo processo, il componente padre si ritroverà una lista riempita di elementi definiti nel coponente filio 
   e passare la list ad un altro componente figlio.

********** FORM PER L'INSERIMENTO DI UN NUOVO ELEMENTO IN UNA LISTA ***********

Quando dobbiamo gestire una lista di elementi in cui possiamo aggiungere, eliminare o cancellare elementi conviene farlo trami almeno 2 widget custom, un element LIST e uno ITEM (ovviamente è necesario un elmento che contiene l'elemento LIST).
L'inserimento di un nuovo elemento nella lista può avvenire tramite una dialog, ne esistono di diversi tipi e una di queste è showModalBottomSheet in cui la dialog spunta fuori dal basso.
Nel form i campi possono essere validati, o con una funzione specifica oppure invece di usare il campo TextField si può usare il campo TextFormField che contiene la proprietà "validation."
Tra la catena ELEMENTO CONTENITORE -> ELEMENTO LISTA -> ELEMENTI ITEM è possibile definire delle funzioni da passare ai widjet figli (es: aggiungere un elmento alla lista o eliminare un elemento).
Per eliminare un elemento invece di mettere il pulsante con l'icona del cestino, possiamo abilitare lo swipe che cancella l'elemento. Dopo l'elemento mostriamo uno snackBar per confermare l'eleminazione e diamo anche la possibilità di cancellare l'operazione

Es:  
void _handleRemoveExpenses(Expense expense){
    int indexExpense = _registerExpense.indexOf(expense);

    setState(() {
      _registerExpense.remove(expense);
    });
    ScaffoldMessenger.of(context).clearSnackBars();
    ScaffoldMessenger.of(context).showSnackBar(
      SnackBar(
          content: Text("Expense deleted"),
          duration: Duration(seconds: 2),
          action: SnackBarAction(label: "Undo", onPressed: (){
            setState(() {
              _registerExpense.insert(indexExpense, expense);
            });
          }),
      )
    );
  }
