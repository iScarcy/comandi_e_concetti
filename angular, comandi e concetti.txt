  public users(): Observable<User[]>
  {
    var uri:string = "https://jsonplaceholder.typicode.com/users";
    return this._http.get<Array<IUser>>(uri).pipe(
        map( users =>
          {  
           return users.map(user => new User(user.id, user.name, user.username, user.email))   
          })
    );

  }

  public ngOnInit(): void {
     this.handleUsers();

    //subscribe: registro l'osservable
    this._userService.users().subscribe(users =>{
      this.users = users;
    
    });
  }

******************* FORM ***********************

TEMPLATE DRIVER FORM, si caratterizzano per avere le regole di validazione nell'html del template e non dentro il codice.

TWO WAY DATA BINDING, si realizza con una direttiva particolare specifica per i form.

E' necessario carica un modulo. In app.module.ts, inserire in "imports" FormsModule -

<form (ngSubmit)="handleLogin()">
    <label>email:</label>
    <input name="email" type="email" [(ngModel)]="email" >
    <label>password:</label>
    <input name="password" type="password" [(ngModel)]="password" >
    <button>Accedi</button>
</form>

REGOLE: 

[(ngModel)]="email" con questa sintassi leghiamo un attributo html ad una proprietà del componente, Dal codice leggiamo il valore che l'utente inserise dal html. Il valore della proprietà in questione può essere modificato sul codice, da qualsiasi metodo, e può essere modificato anche dall'utente sull'html quando modifica il calore del campo. QUESTA DOPPIA POSSIBILITA' DI MODIFICA E' QUELLO CHE DI DA' IL TWO WAY DATA BINDING

(ngSubmit)="handleLogin()" al submit del form viene invocato il metodo indicato, in questo caso "handleLogin"

	
VALIDAZIONE DEI FORM 

Con i template driver form, la validazione avviene sul html del template e non nel componente. E' sufficiente mettere delle validazioni html5 sui campi (required, email, password, maxlenght, minlenght, etc.)
la validazione del form parte nel momento il cui, si passa al componente un istanza del form (dove avviene la validazione)
es: <form (ngSubmit)="handleLogin(f)" #f="ngForm"> nel form dichiaro una variabile f che contiene l'instanza del form rappresentata dall'ogetto ngForm 
	dopo di che passo tale instanza al metodo handleLogin che dovrà avere questa firma  "public handleLogin(f:NgForm)"
	
GESTIONE MESSAGGI D'ERRORE

per gestire i messaggi d'errore di validazione sui campi usiamo : REFERENCE TEMPLATE VARIABLE

ovvero:  <input name="email" type="email" [(ngModel)]="email" #e="ngModel" required email>
-> ngModel viene usato sia per il two way buinding ma anche come puntatore all'oggetto che angular ha creato per quel campo, questo avviene tramite l'istruzione #e="mgModel" dove "#e" è il nome di una variabile


Questo è un esempio di campo input html validato seguito la gestione dei possibili errori di validazione dello stesso campo

<input name="email" type="email" [(ngModel)]="email" #e="ngModel" required email>
<div *ngIf="e.touched && e.invalid">
	 <p *ngIf="e.hasError('required')">Campo obbligatorio</p>   
	 <p *ngIf="e.hasError('email')">Email non valida</p>   
</div>

mettiamo *ngIf="e.touched && e.invalid" per mostrare gli errori solo se l'utente è entrato nel campo e se il form è invalido
con la proprietà e.hasError chiediamo al nostro puntatore all'oggetto html se si è verificato un determinato errore, è sufficiente mettere tra parentesi la proprietà html che si vuole controllare. Ovviamente deve essere una proprietà che è stat inserita nell'html sul campo interessato. 


********************** LIFE CYCKE HOOKS, ovvero CICLO DI VITA DEI COMPONENTI ****************

-> ngOnChanges <-

viene scatenato più volte durante la creazione delle pagine, può scatenarsi anche durante l'interazione dell'utente.
Si scatena ogni qualvolta c'è un cambiamento di stato di un componente, i cambiamenti per ANGULAR i cambiamenti delle proprietà decorate con INPUT
Nella fase di elaborazione del costruttore, ANGULAR scatena ngOnChanges (prima di arrivare all'ngOnInit) tante volte quanto sono le proprietà in input


  ngOnChanges(changes: SimpleChanges): void {
    if('user' in changes)
    {
      // se questa condizione è vera significa che "user" è la proprietà che ha subito la modifica
      //changes.user.currentValue = valore attuale, quello che possiamo vedere a seguito della modifica
      //changes.user.previousValue = valore prima della modifica
      //changes.user.firstChange, ci dice se  la prima volta che il valore del componente è cambiato
    }
  }
  
-> ngOnInit <-
viene eseguiot al termine dell'alavorazione di tutte le direttive (comprese proprietà in input e output)
di uno specifico selettore. In questo memento, tutte le proprietà decorate con @Input sono valorizzate e accessibili
Posto ideale per eseguire chiamate ad interfaccie esterne

-> ngDoCheck <-
permette di eseguire controlli al termine del digest cycle di ANGULAR
SPIEGAZIONE: quando avviene un cambiamento, si scatena ngOnChanges e subito dopo angular fa un serie di controlli su tutta la sua alberatura
			 per verificare che quel cambiamento che è stato fatto sia gestito nell'intera struttura dell'applicazione; questo è il DIGEST CYCLE.
			 Dopo tutti questi controlli, se l'utente volesse fare ulterirori controlli e/o azioni angular richiama ngDoCheck

**************************************** LOGGER *************************************************

L'idea è creare un servizio di gestione degli errori che quando si verifica un errore lato client, 
faccia una chiamata rest al server inviando l'errore
 
 
 export class LoggerService extends ErrorHandler{

  constructor(private _http: HttpClient) { 
    super();
    console.log("LOGGERRR !!!!")
  }

  public override handleError(error: any): void {
    //mando l'errore client sull'app sul server
    this._http.post("indirizzo-server-app",{
      error
    })
    super.handleError(error);
  }
}
