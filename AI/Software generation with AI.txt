   MCP vs RAG 

   MCP = Model Context Protocol -> "let the model do things via tools/APIs" 
   RAF = Retrieval-Augmented Generation -> "let the model know things from your sources"

  Architectures at a glance - Architettura in sintesi

  MCP stack: LLM <-> MCP client <-> MCP server (tools/resources)
  RAG stack: LLM <-> Retriver (vector/keyword) <-> Knowledge store (docs/DB)

  Combined loop: Retrive -> Decide -> Act -> Explain

  When to prefer MCP:
    - you must change a system state (CRUD, workflows, jobs)
    - you need determinisim & auditability
    - You need integration with existing APIs
    - you want safety: sandboxing, allowlist, strinct scopes 

  When to prefer RAG: 
    - Answers must include up-to-date or private Knowledge
    - You must reduce hallucinations and show citations
    - Content changes frequently
    - Need explanations grounded in your corpus

   Use case 
    MCP-only: schedule a job, post a message, export a report, update a record
    RAG-only: answer policy questions, summarise docs with citations, compare versions
    Combinated (Raccomanded): 

   Security:
    MCP: least privilege per tool; allowlist, strict schemas; full auting
    RAG: index only autorised content, encorce ACLs at query timeouts
    Both: plicy prompts, rate limits, human in the loop for sensitive actions

   performance
    MCP: acoid chatty loops, batch calls, cache tool results: desing narrow tools
    RAG cache embeddings: restrick top-k; use re-ranking; pre-compute summaries
    Global: smaller models + stronger Retrival

   Conclusion:
    IF it must act: start with MCP
    IF it must know: start with RAG
    IF both: RAG -> Decide -> MCP -> Summarise 

    Evaluate 
      - RAG: groundedness, citation accuracy, retrieval hit rate
      - MCP: task success, errore rate, time to complet
